# Product backlog

|---|---|---|---|---|
| PB-01 | F1 - Up file lưu chứng | Là đương sự, tôi up file lên app, server băm file rồi bỏ, chỉ giữ hash. | F1-AC1: Chỉ lưu hash, không lưu file.<br>F1-AC2: File được băm theo luồng trong bộ nhớ rồi bỏ, không ghi ra đĩa hay database. | Must |
| PB-02 | F1 | Là đương sự, tôi nhận biên nhận (mã, giờ server). | F1-AC1: Giờ do server cấp.<br>F1-AC2: Biên nhận tạm có chữ ký hệ thống ngay lúc lưu.<br>F1-AC3: Biên nhận hoàn chỉnh (đường dẫn Merkle, mã giao dịch) sau khi neo xong. | Must |
| PB-03 | F1 | Là hệ thống, có file là tôi tự tìm ra bản ghi đã up; Tòa không truy cập được file ở bước up. | F1-AC1: Đương sự đưa lại file thì hệ thống tự tìm ra bản ghi mình đã lưu chứng (giờ, người lưu), không cần nhập mã. Chỉ đương sự tra cứu bằng file; Tòa và tài khoản khác không tra cứu bằng file. Đưa file khác thì không tìm ra. | Must |
| PB-04 | F2 - Nộp chứng cứ + khởi kiện tại Tòa | Là đương sự, tôi nộp đơn kèm chứng cứ trực tiếp tại Tòa (USB, đưa trực tiếp), không qua app và không phải up lại. Nộp nhiều file trong 1 lần thì được gom thành 1 lô. | F2-AC1: App không có chức năng nộp đơn hay chứng cứ lên Tòa. | Must |
| PB-05 | F2 | Là thư ký, khi đương sự nộp tại Tòa (USB, trực tiếp), tôi nạp file vào hệ thống và hệ thống tự hash, tôi không nhập hash. | F2-AC1: Thư ký nạp file, hệ thống tự tính hash tại chỗ, file chỉ được băm rồi bỏ, không lưu vào database.<br>F2-AC2: Ngày, giờ, nơi nộp do hệ thống ghi.<br>F2-AC3: Hệ thống không lưu file, chỉ giữ hash. | Must |
| PB-06 | F3 - Hệ thống tự so hash khi nộp | Là hệ thống, khi nộp tôi tự so từng file với hash đã up. | F3-AC1: Giống hash đã up: KHỚP BẢN LƯU CHỨNG.<br>F3-AC2: Khác: KHÁC BẢN LƯU CHỨNG (chưa kết luận người sửa — việc của Tòa).<br>F3-AC3: Chưa từng up: KHÔNG CÓ MỐC ĐỂ SO, hash lúc nhận làm mốc.<br>F3-AC4: Kết quả do hệ thống tính, không nhập tay. Thư ký vẫn chọn bản A để so. | Must |
| PB-07 | F3 | Là hệ thống, mỗi lần nộp tôi tạo 1 hash tổng của lô (ngày, giờ, nơi nộp, số lượng, hash từng file). | F3-AC1: Lô N file ghi N+1 hash: N hash file + 1 hash tổng. Ví dụ nộp 3 file ghi 4 hash (3 file + 1 tổng). | Must |
| PB-08 | F3 | Là hệ thống, về sau tôi tính lại hash tổng để báo KHỚP / KHÁC BẢN ĐÃ GHI; nộp bổ sung tạo lô mới. | F3-AC5: Tính lại hash tổng từ file thư ký chọn lại trong hồ sơ Tòa + ngày, giờ, nơi nộp, số lượng đọc từ bản ghi lô; so với hash tổng đã ghi lúc nhận lô. Thêm, bớt, đổi file hay đổi giờ/nơi/số lượng = KHÁC BẢN ĐÃ GHI, ngược lại KHỚP BẢN ĐÃ GHI. Mỗi lần tính lại ghi thêm 1 dòng IntegrityCheck, không sửa bản ghi lô.<br>F3-AC6: Nộp bổ sung tạo lô mới trong cùng vụ, đánh số thứ tự sau lô cũ, có hash tổng riêng. Lô cũ không bị sửa, hash tổng lô cũ giữ nguyên. | Must |
| PB-09 | F5 - Xem kết quả | Là thẩm phán, đương sự, luật sư, tôi chỉ thấy kết quả cuối kèm ngày, giờ, nơi nộp, số lượng, không thấy mã hash. | F5-AC1: Mỗi chứng cứ hiện KHỚP BẢN LƯU CHỨNG / KHÁC BẢN LƯU CHỨNG / KHÔNG CÓ MỐC ĐỂ SO; cả lô hiện KHỚP BẢN ĐÃ GHI / KHÁC BẢN ĐÃ GHI; kèm ngày, giờ, nơi nộp, số lượng.<br>F5-AC2: Không màn hình, biên bản nào hiện mã hash.<br>F5-AC3: Mọi màn hình hiện kết quả có dòng chú thích cố định: "Chỉ so với bản đã lưu, không xác định thật giả."<br>F5-AC4: Mỗi kết quả (từng chứng cứ và cả lô) kèm "Kiểm tra lúc [giờ]": giờ hệ thống tính kết quả đó. | Must |
| PB-10 | F6 - Nhật ký không sửa được | Là hệ thống, tôi lưu hash chỉ ghi thêm, không sửa/xóa được. | F6-AC1: Tài khoản ứng dụng không có quyền UPDATE/DELETE trên các bảng chỉ ghi thêm; trạng thái thay đổi được ghi thêm vào bảng riêng. Sửa một bản ghi thì verifier báo lệch. | Must |
| PB-11 | F6 | Là hệ thống, tôi neo mã gom cả ngày lên chuỗi công khai (bản demo: neo sau mỗi lần nộp). | F6-AC2: Sửa dữ liệu thì mã neo công khai lệch, phát hiện được.<br>F6-AC3: Chuỗi chỉ chứa mã neo, không có file. | Must |
| PB-12 | F4 - Giám định | Là hệ thống, khi giám định tôi tự so hash ở bước gửi, nhận, về. | F4-AC1: Chỉ gửi khi file vẫn giống hash đã ghi nhận (E), không phải hash lúc lưu chứng (A).<br>F4-AC2: Nhận hoặc về mà khác (E): KHÁC BẢN ĐÃ GHI, biết khác ở bước nào. | Should |
| PB-13 | F4 | Là thư ký, tôi ghi thay các bước giám định (gửi đi, nhận về); người giám định không dùng hệ thống. | F4-AC1: Thư ký ghi thay mọi bước (gửi đi, nhận về) kèm ngày, giờ; người giám định không có tài khoản trong hệ thống. | Should |
| PB-14 | F1 | Là đương sự, sau khi neo tôi nhận biên nhận hoàn chỉnh để tự kiểm tra mà không cần hỏi Tòa. | F1-AC5: Biên nhận chuyển từ "chờ neo" sang "đã neo", có đủ dữ liệu để tự kiểm tra (mã neo, đường dẫn chứng minh); tải, lưu được. Neo lỗi thì hệ thống tự thử lại. | Must |
